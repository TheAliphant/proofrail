## Requirement → existing evidence → funded work → proof

"Existing evidence" refers **only** to the public ProofRail receipt/verification MVP and limited SDK-readiness spike; other cells are proposed deliverables. Unless an evidence link exists, no live Stellar facilitator, Bazaar, settlement, Soroban `upto` contract, audit or upstream acceptance is claimed.

## Stage gates (not achieved by this documentation update)

1. **Eligibility:** SCF invitation + written confirmation the July 2026 SCF #45 x402/Bazaar RFP can be submitted in #46. The deadline alone is not proof of eligibility.
2. **Dependency baseline:** Re-pin to latest stable compatible Stellar SDKs and run all spike tests; report resulting lockfile/commit and any incompatible spec changes.
3. **T0/T1:** Threat model, fee/auth/retention policies; public free testnet service, `exact` verification and paid-call proof with wire captures, `EXTENSION-RESPONSES` and seller helpers.
4. **T2:** Evaluated query/search, MCP integration, `upto` spec/contract implementation evidence, smart-account spending-policy tests and upstream collaboration.
5. **T3:** Third-party security review, pubnet deployment, both-network/both-scheme canonical E2E and transaction hashes, public telemetry/runbook, two independent integrations and Stellar Developer Docs contribution.

## Scope boundary

ProofRail's public receipt/CLI/x402-challenge/Base ERC-20 verification capabilities are **existing**; Stellar facilitation, Bazaar, `upto`, production metrics and external approvals are **proposed**. The private Agent Labour Engine remains private. Grant work creates open Stellar payment/discovery infrastructure and optional ProofRail interop evidence, not private provider ranking, commercial strategy, credentials or private runtime artifacts. The default Bazaar is off-chain; batch-settlement, auth-capture and an on-chain registry remain out of baseline scope.
